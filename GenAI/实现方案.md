# NFC 打卡闹钟 · 实现方案

> 对应需求：[需求文档.md](./需求文档.md)
> 技术栈：uni-app x（vapor 蒸汽模式）+ 自研 UTS 插件，仅 Android，纯本地无网络。

---

## 1. 技术边界与前置约束

| 项 | 结论 |
| --- | --- |
| 框架 | uni-app x，manifest 已开启 `"vapor": true` |
| 平台 | 仅 `app-android`，所有原生能力用 `#ifdef APP-ANDROID` 隔离 |
| 后端 | 无，全部本地（SharedPreferences + 页面内存态） |
| 关键约束 | 蒸汽模式页面逻辑编译为 JS，**不能直接调用 Android 原生 API**；NFC / 闹钟 / 通知 / 震动必须封装进 UTS 插件 |
| 调试方式 | **必须自定义基座或云打包**（插件包含 AndroidManifest、Service、权限），标准基座不生效 |
| 页面语言 | `<script setup>`，只依赖插件导出的类型与方法 |
| 第三方依赖 | **零第三方插件**（NFC 自研，不使用插件市场付费插件） |

## 3. 总体架构

```
pages/calendar   日历 + 实时时钟 + 延迟按钮 + 刷卡状态提示
pages/settings   卡片录入 / 时间 / 间隔 / 今日不打卡 / 权限健康检查
        │  只调用插件 API（经 common/plugin.uts 适配层）
        ▼
uni_modules/nfc-clockin-alert/utssdk
    ├── interface.uts                 统一类型 + 函数签名（页面类型来源）
    └── app-android/
        ├── index.uts                 对外 API 实现
        ├── Store.uts                 SharedPreferences 读写（插件侧唯一数据源）
        ├── NfcReader.uts             enableReaderMode 读卡 UID
        ├── Scheduler.uts             AlarmManager 精确闹钟调度
        ├── AlarmReceiver.uts         静态广播接收器（闹钟到点）
        ├── ReminderWorker.uts        闹钟回调后执行：发通知 + 震动 + 状态推进
        ├── Notifier.uts              NotificationChannel + 通知构建
        ├── BootReceiver.uts          BOOT_COMPLETED / MY_PACKAGE_REPLACED 重排
        └── AndroidManifest.xml       权限 / receiver 注册
```

**核心决策：所有业务数据（配置、记录、当日状态）由插件层 SharedPreferences 统一存储。**
原因：`AlarmReceiver` / `BootReceiver` 可能在 App 进程未启动时执行，此时 uni 运行环境尚未初始化，`uni.getStorageSync` 会抛 `lateinit property currentApp has not been initialized`（已知 issue 17294）。页面不直接读写 storage，只通过插件接口读写。

## 4. 提醒实现方案（最终选型：方案 A）

### 4.1 两种方案差异对比

| 维度 | 方案 A：AlarmManager 链式单发通知 | 方案 B：AlarmManager + 前台服务常驻 |
| --- | --- | --- |
| 实现方式 | 每次到点由广播接收器发一条通知，再注册下一个间隔闹钟 | 到点启动 ForegroundService，服务内 Handler 循环发通知 |
| 进程存活要求 | 无，每次都唤醒系统广播 | 需要前台服务常驻不被杀（含常驻通知） |
| 可靠性 | 高。系统级唤醒，进程被杀也能收到 | 依赖前台服务存活，国产 ROM 仍可能杀 |
| 时间精度 | 由 AlarmManager 精度决定，可容忍偏移 | Handler 定时，精度高但仅在服务存活时 |
| 耗电 | 低 | 较高（常驻服务） |
| 复杂度 | 低，无 Service 声明与前台通知 | 高，需要前台服务类型、常驻通知、Android 14 服务类型声明 |
| 用户观感 | 状态栏出现常驻通知 | 状态栏长期存在一条"运行中"通知 |
| 延迟/停止控制 | 取消已注册闹钟即可，实时生效 | 服务内改状态，进程被杀虫后不可靠 |
| 适用场景 | 「每分钟发一条消息 + 震动，不需要响铃，容忍约 5 分钟偏移」 | 需要秒级精度、持续响铃或实时音频 |

**结论：采用方案 A。**

理由：
1. 需求只需**每分钟发一条通知 + 震动一次，不需要响铃**，完全不需要常驻服务维持循环；
2. 允许时间偏移（容忍约 5 分钟），AlarmManager 的 `setAndAllowWhileIdle` 精确度足够；
3. 进程被杀后仍能通过系统广播唤醒，比前台服务更抗杀；
4. 无长期常驻通知，用户观感更好，也避免 Android 14 前台服务类型等额外适配；
5. 延迟 5 分钟、停止提醒均可通过「取消已注册闹钟 + 重新注册」即时生效。

### 4.2 提醒链路

```
设置保存 / 应用启动 / 开机 / 打卡 / 跳过
        │
        ▼
Scheduler.reschedule()
        │  1. 取消所有已注册闹钟
        │  2. 判断当日状态（checked/skipped → 直接排下一个工作日）
        │  3. 计算下次触发时间戳 nextAt
        ▼
AlarmManager.setAndAllowWhileIdle(RTC_WAKEUP, nextAt, PendingIntent)
        │
        ▼（到点）
AlarmReceiver.onReceive
        │  1. 读取 config / todayState（插件 SharedPreferences）
        │  2. 若今日已 checked/skipped → 只做 reschedule(明日)，退出
        │  3. 发通知（内容区分：是否已绑定卡片）
        │  4. 震动一次（Vibrator，200~400ms）
        │  5. 若处于 deferred → 判断是否到期
        │  6. reschedule(nextAt = 当前 + intervalMinute * 60_000)
        ▼
循环直至 checked / skipped / 应用被取消
```

### 4.3 时间与精度策略

- 使用 `AlarmManager.setAndAllowWhileIdle()`（RTC_WAKEUP），不申请 `SCHEDULE_EXACT_ALARM`，避免用户需手动授权精确闹钟的复杂引导。
- `setAndAllowWhileIdle` 在 Doze 下的最小间隔约 9 分钟，与「容忍 5 分钟偏移」基本匹配；对每分钟间隔的实际表现是“系统允许时尽快触发”。
- 记录 `scheduledAt` 与实际触发时的比较，若因 Doze 延迟导致错过多次，**不补发历史通知**，只发当前一条，避免通知轰炸。
- 闹钟到点后，下次触发时间统一以「实际触发时间 + 间隔」计算，不做累积补偿。

### 4.4 延迟 5 分钟

- 点击「延迟 5 分钟」→ `Store.setDayStatus('deferred', deferUntil = now + 5min)` → `Scheduler.reschedule()` 把下一次触发改为 `deferUntil`。
- `deferUntil` 到期后触发一次通知，并把状态改回 `ringing`，后续按 `intervalMinute` 继续。
- 重复点击延迟即重置计时。

### 4.5 停止提醒

- 打卡成功 / 今日跳过：写入当日状态 → `Scheduler.cancelAll()` → `Scheduler.reschedule()`（此时会排到下一个工作日）→ 取消已发出但未点击的通知可选（保留当前通知，让用户看到结果）。

### 4.6 权限与兼容

| 权限 | 用途 | 获取方式 |
| --- | --- | --- |
| `NFC` | 读卡 | AndroidManifest，无需运行时申请 |
| `POST_NOTIFICATIONS` | 通知（Android 13+） | 运行时申请，插件提供 `requestNotificationPermission()` |
| `VIBRATE` | 震动 | AndroidManifest |
| `RECEIVE_BOOT_COMPLETED` | 开机重排 | AndroidManifest |
| `WAKE_LOCK` | 广播唤醒 | AndroidManifest |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | 引导电池优化白名单 | 插件提供跳转系统设置 |

- 不使用 `SCHEDULE_EXACT_ALARM`，不做精确闹钟授权引导。
- 设置页提供「运行环境检查」区块：通知权限状态、电池优化状态，未通过时给出红色提示与跳转按钮。
- 国产 ROM（小米/华为/OPPO/vivo）自启动限制：设置页提供说明文案 + 跳转应用设置页按钮（`openAppSettings()`），不承诺强制生效。

## 5. NFC 实现方案

### 5.1 读取方式

- 采用 `NfcAdapter.enableReaderMode(activity, callback, flags, bundle)`。
- flags：`FLAG_READER_NFC_A | FLAG_READER_NFC_B | FLAG_READER_NFC_F | FLAG_READER_NFC_V | FLAG_READER_SKIP_NDEF_CHECK`。
- 不用 `enableForegroundDispatch`：需 PendingIntent + IntentFilter + tech-list，且易被系统 NFC 弹窗/钱包类应用抢占，时序不稳定。
- `onTagDiscovered` 在 Binder 线程回调，插件内部切主线程再回调给页面。
- 模块级持有 `ReaderCallback` 与 `NfcAdapter` 引用，避免被 GC 回收导致回调丢失。
- 插件内部监听 Activity 生命周期，`onPause` 时 `disableReaderMode`，`onResume` 时若仍在扫描态则重新 `enableReaderMode`（解决"页面切换后 reader mode 失效"）。

### 5.2 UID 处理

- `tag.getId()` 返回 `ByteArray`，按字节大端顺序转**大写十六进制字符串**（无分隔符），如 `04A1B2C3D4E5F6`。
- 录入与校验使用相同的转换函数，保证一致。
- 兼容 4 字节（Mifare Classic）与 7 字节（ISO14443-A / 手机模拟卡）UID。

### 5.3 卡片录入流程

1. 设置页点击「录入卡片」→ 进入扫描态（页面显示遮罩 + "请将卡片贴近手机 NFC 感应区"）。
2. 插件 `startScan({ once: true, timeout: 60000 })`。
3. 读到卡片 → `Store.saveCardId(uid)` → `uni.showToast('卡片录入成功')` → 自动退出扫描态。
4. 超时 / 用户点取消 → `stopScan()`，提示"未读取到卡片"。

### 5.4 打卡校验流程（日历页）

- 日历页可见期间自动开启扫描（`startScan({ once: false, timeout: 0 })`），页面 `onHide` / `onUnload` 时 `stopScan()`。
- 读到卡片后由页面与已绑定卡号比对：
  - 未绑定卡片 → Toast「请先在设置中录入 NFC 卡」
  - 卡号不匹配 → Toast「卡片不匹配」
  - 当日已是 `checked` / `skipped` → Toast「今日已完成记录」
  - 匹配且今日未完成 → `Store.markChecked(today)` → `Scheduler.reschedule()` → 刷新页面状态
- 未开启 NFC 时，页面顶部显示"请开启系统 NFC"提示条，点击调用 `requestEnableNfc()` 跳系统设置。

### 5.5 自研插件接口清单

```ts
// interface.uts（页面可直接引用类型）

export type CheckinStatus = 'idle' | 'ringing' | 'deferred' | 'checked' | 'skipped'

export type ClockConfig = {
  cardId: string
  startHour: number
  startMinute: number
  intervalMinute: number
  enabled: boolean
}

export type DayRecord = {
  date: string            // yyyy-MM-dd
  status: 'checked' | 'skipped'
}

export type TodayState = {
  date: string
  status: CheckinStatus
  deferUntil: number      // 0 表示无延迟
  nextAlarmAt: number     // 下次提醒时间戳，0 表示无
  ringCount: number       // 今日已提醒次数
}

export type ScanOptions = {
  once?: boolean
  timeoutMs?: number
  onTag: (uid: string) => void
  onError?: (code: number, message: string) => void
}

export type Result<T> = { ok: boolean; data: T; message: string }
```

```ts
// 导出的函数（@/uni_modules/nfc-clockin-alert）

// 配置
getConfig(): ClockConfig
saveConfig(c: ClockConfig): void        // 内部会触发 reschedule

// 记录
getRecords(): DayRecord[]
getCheckedCount(): number

markChecked(date: string): boolean
markSkipped(date: string): boolean
defer(minutes: number): void

// NFC
isNfcSupported(): boolean
isNfcEnabled(): boolean
requestEnableNfc(): void
startScan(options: ScanOptions): void
stopScan(): void

// 调度

// 权限

```

## 6. 数据模型（插件 SharedPreferences）

```
KEY_CONFIG        : JSON  ClockConfig
KEY_RECORDS       : JSON  Map<date, 'checked'|'skipped'>
KEY_TODAY_STATE   : JSON  { date, status, deferUntil, ringCount }
KEY_NEXT_ALARM    : long  下次触发时间戳（用于页面展示与开机恢复）
```

- 日期键格式：`yyyy-MM-dd`（本地时区）。
- 跨天处理：每次读写前比对 `todayState.date` 与当前日期，不一致则重置 `todayState` 为 `idle`（`deferUntil=0`，`ringCount=0`）。
- 历史记录不做清理，按需求"历史累计打卡天数"永久累计。

## 7. 状态机

```
            到点触发
idle ──────────────────> ringing ──点延迟──> deferred(5min)
  ▲                        │                    │
  │                        │                    │ 到期
  │                        │<───────────────────┘
  │                        │
  │           ┌────────────┴─────────────┐
  │           │ 刷卡匹配                 │ 3 次确认跳过
  │           ▼                          ▼
  │        checked                    skipped
  │           │                          │
  └───────────┴──── 次日 00:00 后重置 ────┘
```

- `idle` 也可能直接进入 `checked`/`skipped`（用户在到点前提前打卡/跳过）。
- `ringing` 与 `deferred` 下刷卡 / 跳过的效果与 `idle` 一致，均写入记录并终止当日流程。

## 8. 页面详细设计

### 8.1 日历页 `pages/calendar/calendar.uvue`

区块自上而下：

1. **自定义导航栏**：左侧标题「NFC 打卡闹钟」，右侧「设置」图标按钮（`uni.navigateTo` 到设置页）。
2. **统计卡**：大字号「累计打卡 N 天」，下方「下次提醒：周一 08:30」。
3. **NFC 状态条**（条件显示）：
   - 未开启 NFC → 橙色条「NFC 未开启，点击开启」
   - 未绑定卡片 → 橙色条「尚未录入 NFC 卡，请前往设置」
4. **月历卡片**：
   - 头部：`‹ 2026年11月 ›`，左右切换月
   - 星期头：一二三四五六日
   - 网格：`display: flex; flex-direction: row; flex-wrap: wrap;`，每格 `width: 14.28%`
   - 单元格状态样式：
     - 已打卡：绿色实心圆底 + 白色文字
     - 已跳过：橙色描边圆 + 橙色文字（与打卡明确区分）
     - 今天：蓝色细边框
     - 未来日期：浅灰文字
     - 非工作日：不特殊标记（与工作日同色，仅文字浅灰）
   - 图例：`● 已打卡`　`○ 已跳过`
5. **实时信息卡**：当前日期 + 实时时间（每秒刷新） + 下次计划打卡时间。
6. **提醒浮层**（`ringing` / `deferred` 时显示，固定底部卡片）：
   - 文案：「打卡提醒已触发」/「已延迟，剩余 04:32」
   - 「延迟 5 分钟」按钮
   - 提示「请将 NFC 卡贴近手机感应区完成打卡」

实时时钟：页面 `onShow` 时启动 `setInterval(1000)`，`onHide`/`onUnload` 时清理；同时每秒调用一次 `getTodayState()` 的轻量版（或每 2 秒轮询一次）。
> 后台事件无法推送回页面，页面回到前台时主动刷新一次状态。

### 8.2 设置页 `pages/settings/settings.uvue`

区块自上而下：

1. **NFC 卡片**
   - 状态行：`已绑定  04A1B2C3D4E5F6` / `未绑定`
   - 「录入卡片」按钮 → 扫描遮罩；「解除绑定」按钮（二次确认）
2. **开始提示时间**
   - 行标题 + 右侧显示 `08:30`
   - 点击打开 `<picker mode="time">`（Android 5.08+ 支持）
3. **提示间隔时间**
   - 行标题 + 右侧显示 `1 分钟`
   - 点击打开 `<picker mode="selector">`，range 为 1~30 分钟
4. **今日不打卡**
   - 按钮「今日不打卡」
   - 点击 → 连续 3 次 `uni.showModal` 确认，任一次取消即整体中断并 Toast「已取消」
   - 3 次全部确认 → `markSkipped(today)` → Toast「今日已跳过」→ 返回日历页
5. **运行环境检查**
   - 通知权限：已开启 / 未开启（点击申请）
   - 电池优化：已忽略 / 未忽略（点击跳设置）
   - 自启动说明：文案 + 「打开应用设置」按钮
6. 底部「完成」按钮：`uni.navigateBack()`

## 9. 异常与边界处理对照

| 需求场景 | 实现处理 |
| --- | --- |
| 未录入 NFC 卡时到点提醒 | 通知/页面文案改为「请先录入 NFC 卡后完成打卡」 |
| 扫描到不匹配的卡 | Toast「卡片不匹配」，不改状态 |
| 当日已完成打卡或跳过后再刷卡 | Toast「今日已完成记录」，不重复写入 |
| 设备未开启 NFC | 页面状态条 + Toast + 跳系统设置 |
| 今日不打卡中途取消 | 任一次 `showModal` 取消即中断，不改状态 |
| 跨天 | 读写前重置 `todayState` |
| 应用被杀 / 重启 | `BootReceiver` + 应用启动时 `reschedule()` |
| 提醒期间关闭 NFC | 提醒继续，页面提示需开启 NFC 才能打卡 |

## 11. 已知风险

1. **Doze 延迟**：`setAndAllowWhileIdle` 在深度休眠下最小触发间隔约 9 分钟，与"每分钟"有差距；用户已接受约 5 分钟偏移，方案可接受。若后续要求严格 1 分钟，需改为前台服务或申请精确闹钟权限。
2. **国产 ROM 杀后台**：广播类唤醒相对可靠，但部分 ROM 会拦截自启动，导致开机重排失败，须依赖用户手动打开自启动权限，无法代码强制。
3. **通知渠道不可变更**：channelId 必须一次定好，后期改声音/震动需换新 channelId。
4. **自定义基座**：所有原生能力必须打通自定义基座验证，标准基座无法测试。
5. **页面与后台状态不同步**：页面在后台时无法接收广播事件，返回前台必须主动拉取状态。

### 13.4 UTS 编译踩坑与修复记录

| 问题 | 原因 | 修复 |
| --- | --- | --- |
| `'const' declarations must be initialized` | `const x = a and 0xFF` 单行复合表达式无法初始化 | 拆分为先声明 `let value : Int = ...` 再单独赋值 |
| `Too many arguments for getLong` / `找不到名称 L` | `0L` 字面量 UTS 不支持 | 定义 `const ZERO_LONG : Long = 0` 常量为默认值 |
| `参数类型不匹配 Number 预期 Int/Long` | Kotlin Android API 需要 Int/Long，UTS `number` 是 Number | 用 `.toInt()` / `.toLong()` 转换；常量声明为 `Int` / `Long` |
| `参数类型不匹配 Number 预期 Int`（ByteArray 下标） | 循环变量推导为 Number，`ByteArray.get` 需 Int | 循环变量显式 `for (let i : Int = 0; ...)` |
| `实际类型 UTSJSONObject 预期 Function1<Tag,Unit>` | `new NfcAdapter.ReaderCallback({...})` 对象字面量无法实现 Java 接口 | 改为 `class ReaderCallbackImpl implements NfcAdapter.ReaderCallback` |
| `找不到名称 and/or` | UTS 无 `and`/`or` 关键字 | 使用 `&` / `|`（编译为 Kotlin 位运算） |
| 广播接收器类被裁剪 | 仅被 AndroidManifest 引用，未被 UTS 代码引用 | `index.uts` 中 `export { ... } from './Receivers.uts'` + 显式 import |
